📋 SYSTÈME COMPLET DE NOTIFICATIONS ET CONFIRMATIONS

Le système de notifications fournit:
✅ Notifications toast (succès, erreur, avertissement, info)
✅ Dialogues de confirmation pour actions critiques
✅ Animations fluides
✅ Gestion automatique des durées d'affichage

═══════════════════════════════════════════════════════════════════════════════
2. NOTIFICATIONS TOAST
═══════════════════════════════════════════════════════════════════════════════

A. NOTIFICATION DE SUCCÈS
--------------------------
success('Client créé avec succès')
success('Données enregistrées', 3000) // Durée personnalisée (3 secondes)

Exemples d'utilisation:
- Création réussie d'un élément
- Modification enregistrée
- Export terminé
- Envoi de données réussi

B. NOTIFICATION D'ERREUR
------------------------
error('Erreur lors de l\'enregistrement')
error('Champs obligatoires manquants', 5000)

Exemples d'utilisation:
- Échec de validation
- Erreur serveur
- Données manquantes
- Opération échouée

C. NOTIFICATION D'AVERTISSEMENT
-------------------------------
warning('Attention: données non sauvegardées')
warning('Ce client a des factures impayées')

Exemples d'utilisation:
- Avertissements avant action
- Données incomplètes mais acceptables
- Limites atteintes

D. NOTIFICATION D'INFORMATION
-----------------------------
info('Chargement des données en cours...')
info('3 nouveaux messages')

Exemples d'utilisation:
- Informations générales
- État du système
- Messages informatifs

3. DIALOGUES DE CONFIRMATION
═══════════════════════════════════════════════════════════════════════════════

A. CONFIRMATION GÉNÉRIQUE
-------------------------
const handleAction = async () => {
  const confirmed = await confirm({
    title: 'Confirmer l\'action',
    message: 'Voulez-vous vraiment continuer ?',
    type: 'warning', // 'danger', 'warning', 'info'
    confirmText: 'Oui, continuer',
    cancelText: 'Non, annuler'
  })
  
  if (confirmed) {
    // Exécuter l'action
    success('Action effectuée')
  }
}

B. CONFIRMATION DE SUPPRESSION
------------------------------
const handleDelete = async (item) => {
  const confirmed = await confirmDelete(item.nom)
  
  if (confirmed) {
    try {
      deleteItem(item.id)
      success(`"${item.nom}" supprimé avec succès`)
    } catch (err) {
      error('Erreur lors de la suppression')
    }
  }
}

Message par défaut: "Êtes-vous sûr de vouloir supprimer [nom] ? Cette action est irréversible."

C. CONFIRMATION DE SORTIE
-------------------------
const handleClose = async () => {
  const hasChanges = formData !== originalData
  const canExit = await confirmExit(hasChanges)
  
  if (canExit) {
    closeModal()
  }
}

Si hasChanges = false, retourne true immédiatement (pas de dialogue)
Si hasChanges = true, affiche: "Vous avez des modifications non enregistrées. Voulez-vous vraiment quitter ?"

4. EXEMPLES COMPLETS PAR SCÉNARIO
═══════════════════════════════════════════════════════════════════════════════

A. CRÉATION D'UN ÉLÉMENT
------------------------
const handleSubmit = async (e) => {
  e.preventDefault()
  
  if (!formData.nom) {
    error('Le nom est obligatoire')
    return
  }
  
  try {
    await createClient(formData)
    success(`Client "${formData.nom}" créé avec succès`)
    closeModal()
  } catch (err) {
    error('Erreur lors de la création du client')
  }
}

B. MODIFICATION D'UN ÉLÉMENT
----------------------------
const handleUpdate = async () => {
  try {
    await updateClient(clientId, formData)
    success('Client modifié avec succès')
    closeModal()
  } catch (err) {
    error('Erreur lors de la modification')
  }
}

C. SUPPRESSION D'UN ÉLÉMENT
---------------------------
const handleDelete = async (client) => {
  const confirmed = await confirmDelete(client.nom)
  
  if (confirmed) {
    try {
      await deleteClient(client.id)
      success(`Client "${client.nom}" supprimé avec succès`)
    } catch (err) {
      error('Erreur lors de la suppression')
    }
  }
}

D. VALIDATION DE FORMULAIRE
---------------------------
const handleValidate = async () => {
  const confirmed = await confirm({
    title: 'Valider le devis',
    message: 'Êtes-vous sûr de vouloir valider ce devis ? Il ne pourra plus être modifié.',
    type: 'warning',
    confirmText: 'Valider',
    cancelText: 'Annuler'
  })
  
  if (confirmed) {
    try {
      await validateDevis(devisId)
      success('Devis validé avec succès')
    } catch (err) {
      error('Erreur lors de la validation')
    }
  }
}

E. EXPORT DE DONNÉES
--------------------
const handleExport = async () => {
  if (data.length === 0) {
    warning('Aucune donnée à exporter')
    return
  }
  
  try {
    await exportToExcel(data)
    success(`${data.length} lignes exportées avec succès`)
  } catch (err) {
    error('Erreur lors de l\'export')
  }
}

F. ENVOI DE DONNÉES
-------------------
const handleSend = async () => {
  const confirmed = await confirm({
    title: 'Envoyer le devis',
    message: `Envoyer le devis à ${client.email} ?`,
    type: 'info',
    confirmText: 'Envoyer',
    cancelText: 'Annuler'
  })
  
  if (confirmed) {
    try {
      await sendEmail(devisId)
      success('Devis envoyé avec succès')
    } catch (err) {
      error('Erreur lors de l\'envoi')
    }
  }
}

G. FERMETURE DE MODAL AVEC MODIFICATIONS
----------------------------------------
const handleCloseModal = async () => {
  const hasUnsavedChanges = JSON.stringify(formData) !== JSON.stringify(originalData)
  const canClose = await confirmExit(hasUnsavedChanges)
  
  if (canClose) {
    setShowModal(false)
    resetForm()
  }
}

type: 'danger'
- Couleur: Rouge
- Icône: Poubelle
- Usage: Suppressions, actions destructives

- Icône: Triangle d'avertissement

- Icône: Information
- Usage: Confirmations simples, informations

6. BONNES PRATIQUES
═══════════════════════════════════════════════════════════════════════════════

✅ FAIRE:
- Utiliser success() après chaque action réussie
- Utiliser error() pour tous les échecs
- Utiliser confirmDelete() avant toute suppression
- Utiliser confirmExit() pour les modales avec formulaires
- Personnaliser les messages pour être spécifiques
- Inclure le nom de l'élément dans les messages

❌ NE PAS FAIRE:
- Utiliser alert() ou confirm() natifs
- Laisser des actions critiques sans confirmation
- Utiliser des messages génériques ("Succès", "Erreur")
- Oublier les try-catch pour les opérations async
- Enchaîner trop de notifications rapidement
